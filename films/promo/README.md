# LAUNCHPAD ROYALE — launch trailer

60 s, 1920×1080 at 60 fps, built with [filmkit](../../../filmkit). The trailer follows one recorded 24-player match (r1)
from the drop to the last shot, through bankr_bot. A virtual cinematographer shoots it in the real game client:
street-level telephoto cameras, depth of field and 240 fps slow motion. Blender renders the chrome 3D title and the
badge-slab end card. It's an independent side project: nothing in it may read as made or endorsed by any launchpad shown.

| File | What it holds |
|---|---|
| `timeline.js` | Cue sheet (120 BPM, cuts on the 2 s bar grid), `HIT` film times the score lands on, the footage edit decision list (`EDL`: sub-cuts, in-points or `hit`/`hitAt` alignment, speed ramps, zooms, whips) and alpha `LAYERS` (the 3D title). |
| `footage.js` | Loads `footage/manifest.json`, seeks one `<video>` per clip to the exact frame in `film.seek(t)` (at the clip's own fps; neighbour blending only when slow motion runs out of source frames), draws it with zoom/punch/whip, then the alpha layers. Missing clips draw a labelled placeholder. |
| `film.js` | Shots and their grade (letterboxed slow-motion bookends), caption styles (Unbounded / JetBrains Mono, mint + gold), captions, flashes. |
| `score.js` | Synthesized synthwave/trap score on the same cue sheet and hits, with its own master glue + limiter. |
| `fonts/` | Unbounded variable + static Black (SIL OFL 1.1, `OFL.txt`). |
| `capture/` | The capture harness that produces `footage/`. `shots.ts` is the clip library; `cinema-a/b/c.ts` are the cinematic shots (endgame, early match, abilities + zone); `cams.ts` holds `Clip` and the camera helpers. |
| `blender/` | `title.py` (chrome 3D title → `footage/title-logo.webm`, VP9 with alpha) and `endcard.py` (the ten badges as slabs → `footage/end-slabs.mp4`). See its README. |

`footage/` and `output/` are git-ignored: the clips are regenerated by the capture harness, the film by filmkit.

## Re-capturing after game changes

Recording live rounds (`capture/record.ts`) is the slow part (real-time matches). Once `capture/recordings/r1–r4.ndjson`
exist, don't re-record: footage is a deterministic replay of those server streams through the *current* client, so
rebuild the capture client and re-capture. Brand/character renames only need the recordings' `"character":"<old>"`
fields rewritten to the new id. All 46 clips take about 17 min in four parallel slots:

```sh
bun films/promo/capture/build.ts
LR_CAP_SLOT=0 bun films/promo/capture/capture.ts <clips…> &   # slots 0–7, each with its own ports
bun films/promo/capture/capture.ts --still mintdrop@0.9,1.6       # framing checks → /tmp/lr-stills
```

`Clip` (`capture/cams.ts`) accepts `fps` (defaults to 60; set 120 or 240 for true slow motion),
`dof: { aperture, maxblur?, focus?: 'subject' | metres }`, and camera modes `track` (keyed camera
positions panning toward the smoothed focus player; `lookOffset`/`rate`) and `follow` via `chase(yaw, extra)`
(9 m, 10° pitch, 32° FOV). A DOF subject follows the spectated player (or `subjectPoint` on orbits);
the BokehPass runs in HDR after the scene render and before bloom. Existing 60 fps clips need no changes.
The capture records source `fps` in the manifest; `footage.js` seeks at that rate. For transparent overlays,
export entries from `timeline.js`'s `LAYERS` (`{ clip, at, until, in?, speed?, alpha: true }`) pointing
at VP9 WebM clips with an alpha plane (`yuva420p`) in the footage manifest.

## Rendering

```sh
filmkit lint promo                    # caption holds, grid, safe area
filmkit sheet promo                   # contact sheet from the runtime
filmkit render promo --force          # → output/promo/launchpad-royale-promo.mp4 (+ loudness.json, spectrogram)
filmkit sheet promo --video output/promo/launchpad-royale-promo.mp4   # contact sheet from the final file
```

Swapping a take: point a logical clip at another manifest name in `CLIPS` (`footage.js`), or change the EDL entry's
`clip`/`hit` in `timeline.js`.
